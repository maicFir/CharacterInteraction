# Vercel 前端 + 自有服务器后端

适用项目：雨停之前 · After Rain。本文按仓库现有配置整理，涵盖首次部署、自动发布、验证和回滚。所有 `example.com`、仓库地址和模型 ID 均需替换为自己的值；命令未说明目录时在仓库根目录执行。

本指南对应 `.github/workflows/deploy.yml`。配置文件已经提供；尚未收到 Vercel 项目、服务器地址/SSH、域名与模型密钥，因此不表示已实际部署。

## 1. 总体顺序

1. 将代码推送到目标仓库 `maicFir/CharacterInteraction`。
2. 在 Vercel 新建/选择项目，Root Directory 设为 **apps/web**，Framework 为 Next.js，Node.js 22，安装命令用 pnpm（读取根目录 workspace 与锁文件），构建 `pnpm build`，Output Directory 保持 Next.js 默认。
3. 准备 Linux 服务器：建议 4 核/8GB RAM、10GB 以上可用磁盘供 CPU 语音验证，Docker Engine + Compose v2（支持 `up --wait`），SSH 与 curl/tar/bash。更小机器的延迟和内存必须实测，不保证达到对话延迟目标。
4. 为后端配置 `https://api.你的域名`。前端直接连接后端 HTTPS/WSS，不借用 Vercel 函数保持 WebSocket。
5. 在 GitHub 新建 `production` Environment，设置下面的 Secrets 和 Variables。需要上线审批时使用该 Environment 的保护规则。
6. 开启部署开关后，向 main/master 推送或手动运行 Deploy production；先执行测试与构建，通过后才部署。

## 2. GitHub Secrets

在 Repository Settings → Secrets and variables → Actions，或 `production` Environment 中配置。不要发到聊天，不要提交 `.env`。

`DEPLOY_BACKEND` 和 `DEPLOY_VERCEL` 请配置为 **Repository Variables**：工作流在 job 级别用它们判断是否启动，不能仅放在尚未进入的 `production` Environment 中。其他配置可以放入该 Environment。

| Secret             | 必需场景         | 内容                                                                        |
| ------------------ | ---------------- | --------------------------------------------------------------------------- |
| OPENROUTER_API_KEY | 后端部署         | OpenRouter API key                                                          |
| SSH_HOST           | 后端部署         | 服务器 IP 或主机名，不带协议                                                |
| SSH_USER           | 后端部署         | 专用部署用户，需能运行 Docker 并写自己的 home                               |
| SSH_PORT           | 后端部署，可省略 | 默认 22                                                                     |
| SSH_PRIVATE_KEY    | 后端部署         | 部署专用 SSH 私钥，保留完整多行                                             |
| SSH_KNOWN_HOSTS    | 后端部署         | 经你核实的 SSH host key / known_hosts 内容；非22端口使用 `[host]:port` 格式 |
| STT_API_KEY        | 外部STT时        | 本地识别无需填                                                              |
| TTS_API_KEY        | 外部TTS时        | 本地合成无需填                                                              |
| VERCEL_TOKEN       | Actions部署前端  | 有该项目部署权限的 Vercel token                                             |
| VERCEL_ORG_ID      | Actions部署前端  | 个人或团队 scope ID                                                         |
| VERCEL_PROJECT_ID  | Actions部署前端  | Vercel 项目 ID                                                              |

工作流不使用 `StrictHostKeyChecking=no`，也不通过未核验的 ssh-keyscan 自动信任服务器。私钥文件和临时上传包不作为 GitHub artifact 上传。

## 3. GitHub Variables

| Variable                         | 例子/默认                                          | 含义                                                      |
| -------------------------------- | -------------------------------------------------- | --------------------------------------------------------- |
| DEPLOY_BACKEND                   | `true`                                             | 开启真实后端部署；未设置则跳过                            |
| DEPLOY_VERCEL                    | `true`                                             | 开启Vercel CLI部署；未设置则跳过                          |
| OPENROUTER_MODEL                 | `openrouter/free`                                  | 可选，默认免费路由；前端可按会话选择官方文本模型          |
| OPENROUTER_STRUCTURED            | `false`                                            | 支持严格JSON Schema的模型才设true                         |
| ALLOWED_ORIGINS                  | `https://你的项目.vercel.app,https://你的前端域名` | 精确来源，不能包含路径；仅加入自己控制的域名              |
| NEXT_PUBLIC_API_URL              | `https://api.你的域名`                             | 前端构建时公开后端origin，不含/api                        |
| STT_PROVIDER                     | `local`                                            | `local` / `compatible`                                    |
| TTS_PROVIDER                     | `local`                                            | `local` / `compatible`                                    |
| WHISPER_MODEL                    | `tiny`                                             | 免费识别模型大小，改大需要更多内存与下载                  |
| STT_BASE_URL/STT_MODEL           | 外部服务地址/模型                                  | 外部识别协议见README                                      |
| TTS_BASE_URL/TTS_MODEL/TTS_VOICE | 外部服务配置                                       | 外部非实时合成协议见README                                |
| TURN_TIMEOUT                     | `90`                                               | 单轮总超时秒数，范围1–300；前端等待上限100秒，建议保持≤90 |
| API_HOST_PORT                    | `18473`                                            | 宿主机后端端口，1024–65535；冲突时修改，容器内部仍为8000  |
| MANAGED_HTTPS                    | `false`                                            | 默认不接管已有服务器80/443；开启后启动Caddy               |
| API_DOMAIN                       | `api.你的域名`                                     | Caddy管理证书时必填                                       |
| HF_ENDPOINT                      | `https://huggingface.co`                           | 模型下载源；无法访问时可自行选择可信镜像                  |

域名不属于密钥。模型密钥只写服务器运行配置，绝不经 `NEXT_PUBLIC_*`、前端 bundle 或 Vercel build env 暴露。

## 4. 后端工作流做什么

- 验证缺失参数，将密钥和配置序列化为 JSON，避免把配置文本拼进可执行 shell。
- 使用固定 SSH host key，上传仅包含 API、部署配置和模型准备脚本的临时归档。
- 服务器解压到 `~/character-interaction/releases/<commit>-<run>`；发布父目录权限700。
- 构建 Python 3.12 镜像，单进程运行API；密钥以只读 JSON 文件挂载，运行时由非root用户读取。
- API 默认只映射 `127.0.0.1:18473`；模型存放独立命名 volume，不随版本删除。
- 本地 STT/TTS 启用时首次下载模型；后续复用缓存。外部语音模式不下载对应模型。
- 启动前检查目标端口是否可用；仅复用当前 Compose API 自己已有的映射。被其他服务占用时停止部署，不终止占用进程。
- 健康检查使用 API_HOST_PORT；同时生成匹配该端口和 API_DOMAIN 的 `infra/nginx.generated.conf`，不自动修改系统 Nginx。
- 健康检查通过后更新 `~/character-interaction/current` 软链接；失败时尝试重建之前版本。保留历史版本，未自动清理。

健康检查验证进程可达与配置状态，**不代表真实 OpenRouter 额度、语音质量或所有链路都已验收**。模型下载失败会令部署失败并触发回退；检查服务器能否访问配置的模型站。

### HTTPS 两种方式，选择一种

已有 Nginx/网关（当前服务器已有其他项目时采用）：保持 `MANAGED_HTTPS=false`，使用当前 release 的 `infra/nginx.generated.conf` 新增独立 API 域名的 server 块，核对证书路径后运行 `nginx -t`，通过再 reload。生成文件会匹配 API_HOST_PORT；不要覆盖其他项目的配置。后端仅绑定回环地址，无需为18473开放公网防火墙。

空闲主机由项目管理：DNS A/AAAA 指向服务器，允许80/443，确认没有已有服务占用后设置 `MANAGED_HTTPS=true` 和真实 `API_DOMAIN`。Caddy 自动申请有效证书；不会关闭证书校验。IPv6/DNS与证书申请仍需在目标服务器验证。

### 回滚

在服务器进入想回退的 release：

```bash
cd ~/character-interaction/releases/<之前的commit-run>
docker compose --env-file infra/domain.env -f infra/compose.server.yml up -d --build api
```

如果启用过 Caddy，并且同时回退其配置，使用同样命令加 `--profile edge`。环境和密钥随旧 release 保存，轮换密钥时应清理不再需要的旧配置。不要对模型volume执行 `down -v`。

完整回退网关配置的命令为：

```bash
docker compose --env-file infra/domain.env -f infra/compose.server.yml --profile edge up -d --build
```

确认回退后的接口与页面正常，再将 `~/character-interaction/current` 指向该 release 的绝对路径。修改 API_HOST_PORT 后，需要同步更新 Nginx 上游；回滚到不同端口的旧 release 时也需恢复相应上游。现有脚本的自动失败回退仅重建旧 API，不会回退 Caddy，也不是零停机发布；首次发布没有旧版本可恢复。

## 5. Vercel 部署

推荐二选一，避免一次 push 重复部署：

**Actions方式**：项目提前创建并设置Root Directory=apps/web；CLI在monorepo仓库根目录执行 `vercel pull → vercel build --prod → vercel deploy --prebuilt --prod`，遵循Vercel项目的Root Directory配置。设置上述3个Vercel Secrets和公开后端Variable。工作流在CI通过后执行。Vercel CLI使用官方latest，目前未锁定具体CLI版本，首次联调通过后可固定。

**Vercel Git集成方式**：Vercel导入仓库，Root Directory同样设apps/web；在Vercel项目Environment Variables中设置 `NEXT_PUBLIC_API_URL`，GitHub的 `DEPLOY_VERCEL` 保持false。后端仍走Actions。Vercel不会自动读取GitHub Secrets。

两种方式都要把最终前端域名加入后端ALLOWED_ORIGINS。Preview有不同域名时按需精确加入；不要为了省配置把所有vercel.app来源放开。

## 6. 部署后必须亲测

1. Vercel页面默认Mock可用，关闭后网络请求指向后端域名。
2. `/api/health` 可达，WSS成功鉴权，跨域没有报错。
3. 文字输入经过真实OpenRouter与TTS，能听见并看到相同字幕。
4. 手机HTTPS授权麦克风后，语音识别与回复可用。
5. 说话时按住新语音，旧字幕/动作/音频停止；连续输入旧轮不复活。
6. 断网、模型超时与媒体失败后可操作恢复。
7. 录制3–5分钟真实演示，Mock和故障注入明确标注。

服务器地址、Vercel项目ID、域名和Secrets尚未提供时，可以交付完整代码与配置，但不能声称已部署或已跑通真实模型。

参考：[Vercel Monorepo](https://vercel.com/docs/monorepos)、[Vercel Actions部署](https://vercel.com/kb/guide/how-can-i-use-github-actions-with-vercel)、[OpenRouter API](https://openrouter.ai/docs/api/reference/overview)、[OpenRouter结构化输出](https://openrouter.ai/docs/guides/features/structured-outputs)。

## 7. 首次手动部署后端

适用于先验证服务器，再接入 Actions。服务器需已安装 Docker Engine、Compose v2、Git、Python 3；部署用户需要有 Docker 权限。推荐的 4 核/8GB 是本地语音验证起点，Compose 当前对 API 设置了 4GB 内存上限，换大模型时需同步评估此限制。

### 7.1 获取代码并创建配置

```bash
git clone <你的仓库地址> character-interaction-manual
cd character-interaction-manual
umask 077
chmod 700 .
cp apps/api/.env.example infra/backend.env
chmod 600 infra/backend.env
```

用服务器编辑器打开 `infra/backend.env`，至少修改以下值。不要把尖括号占位符原样保留：

```dotenv
ALLOWED_ORIGINS=https://web.example.com
OPENROUTER_API_KEY=<你的密钥>
OPENROUTER_MODEL=openrouter/free
OPENROUTER_STRUCTURED=false
STT_PROVIDER=local
WHISPER_MODEL=tiny
TTS_PROVIDER=local
TURN_TIMEOUT=90
MANAGED_HTTPS=true
API_DOMAIN=api.example.com
HF_ENDPOINT=https://huggingface.co
```

`ALLOWED_ORIGINS` 可填多个逗号分隔的前端 origin，必须包括最终浏览器使用的域名。已有 Nginx 时改为 `MANAGED_HTTPS=false`，并配置仓库中的 `infra/nginx.example.conf`；使用 Caddy 时先完成 DNS 并放通 80/443。

通过配置脚本生成运行文件；此命令会在子 shell 中读取自己编写的配置文件，因此只使用可信内容，值中包含特殊字符时按 shell 语法加引号：

```bash
(
  set -a
  . ./infra/backend.env
  set +a
  python3 scripts/write_deploy_config.py
)
chmod 644 infra/runtime.json
```

配置脚本会固定容器内的 Piper 路径为 `/models/piper/zh_CN-huayan-medium.onnx`，不会采用 `.env.example` 中的本地相对路径。`runtime.json` 包含密钥；文件需允许容器 UID 10001 读取，外层仓库目录通过 `700` 限制其他主机用户访问。`backend.env`、`runtime.json` 和 `domain.env` 均受现有 Git 忽略规则保护，不要强制提交或复制到公开目录。

### 7.2 构建、启动和下载模型

Caddy 方案：

```bash
docker compose --env-file infra/domain.env -f infra/compose.server.yml --profile edge build api
docker compose --env-file infra/domain.env -f infra/compose.server.yml --profile edge up -d --wait --wait-timeout 120
docker compose --env-file infra/domain.env -f infra/compose.server.yml exec -T api .venv/bin/python prepare_models.py
```

已有 Nginx 时，前两条命令去掉 `--profile edge`。手动执行 Compose 时必须自行选择 profile；`MANAGED_HTTPS` 由自动部署脚本读取，Compose 不会根据这个变量自动启用 Caddy。

模型存放在 Compose 项目 `after-rain` 的持久卷中。首次下载可能较慢；脚本按 STT/TTS provider 决定是否下载相应模型，执行成功后再进行真实语音验收。仅 `up --wait` 成功不代表模型已经准备好。默认 Piper 音色的许可情况见 [THIRD_PARTY.md](../THIRD_PARTY.md)，正式用途应确认音色许可。

### 7.3 验证接口

```bash
curl --fail http://127.0.0.1:18473/api/health
curl --fail https://api.example.com/api/health
```

预期返回 `status: "ok"`、`llm_configured: true`，以及实际配置的 `stt`、`tts`。`llm_configured` 只判断配置是否存在，不会验证密钥、模型权限、余额或模型文件。

若先手动部署后切换 Actions，请注意两者使用相同 Compose 项目名，会更新同一套容器和模型卷。手动目录不会自动成为 Actions 的历史 release；首次 Actions 发布失败时需自行恢复手动版本。

## 8. 前端构建与自托管备选

正式方案按第 5 节在 Vercel 部署。前端构建前必须设置 `NEXT_PUBLIC_API_URL=https://api.example.com`，不能填写服务器内网地址、`localhost` 或带 `/api` 的地址。这个值由浏览器使用，并在构建时写入产物；修改后必须重新构建和发布。

若需要在自己的服务器运行前端，可用现有 Next.js 启动脚本。先在 `apps/web/.env.production.local` 写入上述变量，再执行：

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm build
corepack pnpm --dir apps/web start
```

环境要求与根目录 `package.json` 一致：pnpm 10.33.4、Node.js 22.13+（22 系列）或 24+。默认监听 `0.0.0.0:3000`，使用进程管理器保持运行，并通过 HTTPS 反向代理访问；防火墙限制直接访问 3000。将前端最终域名加入后端 `ALLOWED_ORIGINS`。

本地 Docker 联调可直接使用：

```bash
docker compose -f infra/compose.yml up --build
```

它暴露 3000/8000，前端默认 Mock；此 Compose 没有传入真实 LLM 密钥，也不会自动准备语音模型，适用于本地演示。公网后端请使用 `compose.server.yml`。

## 9. 运维与故障排查

Actions 发布后的常用命令：

```bash
cd ~/character-interaction/current
docker compose --env-file infra/domain.env -f infra/compose.server.yml ps
docker compose --env-file infra/domain.env -f infra/compose.server.yml logs --tail=100 api
docker compose --env-file infra/domain.env -f infra/compose.server.yml restart api
```

手动部署时改为进入手动仓库目录。查看网关日志可将最后一个服务名换成 `caddy`（仅启用该服务时）。排查时不要输出或分享运行配置中的密钥。

| 现象                         | 检查与处理                                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------------------- |
| 页面正常但关闭 Mock 后失败   | 检查构建时的 `NEXT_PUBLIC_API_URL`、后端健康接口和浏览器实际请求地址；更新变量后重新发布前端 |
| CORS 报错或 WebSocket 被拒绝 | 核对前端真实 origin 是否加入 `ALLOWED_ORIGINS`，包括协议和端口；更新后端配置并重新部署       |
| HTTPS 页面请求被浏览器拦截   | 后端使用有效 HTTPS，WebSocket 使用 WSS；前端不能连接 HTTP 公网 API                           |
| Nginx 下 WebSocket 连接失败  | 检查 HTTP/1.1、Upgrade/Connection 转发和代理超时，参考仓库 Nginx 示例                        |
| Caddy 无法签发证书           | 核对 A/AAAA 解析、80/443 入站、防火墙及端口占用；无可用 IPv6 时移除错误 AAAA 记录            |
| 健康接口成功，真实回复失败   | 检查 API 日志、OpenRouter 密钥/模型/余额、结构化输出支持和语音模型文件                       |
| 模型下载失败                 | 检查服务器外网、磁盘、`HF_ENDPOINT` 与模型卷权限；修复后重新执行模型准备命令                 |
| 容器退出或语音很慢           | 检查内存/OOM、CPU和并发；先用 tiny 验证，必要时使用兼容外部语音服务                          |
| 手机无法录音                 | 使用可信 HTTPS 并允许麦克风权限；Mock 按住演示不会申请麦克风                                 |
| 重启后会话失效               | 当前会话和音频在内存中，重新创建会话；保持单 worker、单 API 实例                             |
| Actions 跳过部署             | 检查分支是否 main/master、Repository Variables 部署开关是否为字符串 `true`、CI 是否通过      |

当前后端没有账号系统，公网发布前应按实际使用范围在网关补充访问控制或限流，避免模型费用被滥用。不要直接扩成多个 worker 或多个 API 副本；内存会话与 WebSocket 状态尚未共享。

发布验收以第 6 节为准。更新密钥时要重新生成配置并部署，同时清理旧 release 中不再需要的密钥副本。保留模型卷和需要回滚的代码版本；重启、发布和回滚都会使现有内存会话失效。

关闭前端 Mock 后，顶部“模型”可加载官方文本模型列表，搜索、筛选免费模型并查看 token 价格。所选模型在创建会话时提交，后端校验并固定到该会话。更换模型会中断回复并清空会话。环境变量仅定义默认模型；密钥始终留在后端。模型目录需要后端能访问 `https://openrouter.ai/api/v1/models`，缓存 5 分钟。目录成功不保证账户额度、隐私设置、免费配额或场景 JSON 能力满足要求；上线前实测具体模型。

## 本地开发代理与生产隔离

本地用 `corepack pnpm dev:local` 同时启动 API（8000、development、reload）与前端（3002、next dev）；Ctrl+C 会一起停止。也可分别运行 `dev:api` 和 `dev:web`。如需使用 Webpack，可运行 `corepack pnpm dev:local --webpack`。

前端开发配置 `apps/web/.env.development`：`DEV_API_PROXY_TARGET=http://127.0.0.1:8000`。浏览器 HTTP `/backend/api/...` 与 WebSocket `/backend/ws/...` 同源代理到真实后端。代理目标仅在 Next.js 服务端使用，不包含模型密钥；修改后重启前端。后端仍校验 WebSocket 的 Origin，自定义前端端口须同步 ALLOWED_ORIGINS。

生产只设置 `NEXT_PUBLIC_API_URL=https://api.example.com`，执行 build 后用 `start:web`，或由 Vercel 托管。生产不注册 `/backend` 代理，不读取 `.env.development`；本地 `.env.local` 也会影响生产构建，因此开发专用地址请放 `.env.development`。后端 `start:api` 使用 production 且无 reload；服务器继续采用既有 GitHub Actions + JSON secret 部署流程。

## 多项目服务器的生产端口约定

推荐链路：`Vercel 前端 → https://api.你的域名:443（现有 Nginx）→ 127.0.0.1:18473 → API 容器:8000`。

| 项目                 | 生产位置 / 端口                                                  |
| -------------------- | ---------------------------------------------------------------- |
| 本项目前端           | Vercel 管理 HTTPS；自有服务器不运行本项目 Next.js，不占3000/3002 |
| 本项目后端宿主机映射 | `127.0.0.1:18473`，由 GitHub Variable `API_HOST_PORT` 配置       |
| API 容器内部         | `8000`，容器网络隔离，不等于占用宿主机8000                       |
| 公网 HTTPS/WSS       | 使用现有 Nginx 的443与独立 API 域名，不新增80/443监听进程        |

GitHub `production` Environment 可配置 `API_HOST_PORT=18473`、`API_DOMAIN=api.你的域名`、`MANAGED_HTTPS=false`、`ALLOWED_ORIGINS=https://你的前端.vercel.app`、`NEXT_PUBLIC_API_URL=https://api.你的域名`。公共前端 URL 不填写回环地址、18473或容器8000。

18473只是较少使用的默认值，无法保证在目标机器空闲。部署预检会检查实际占用；冲突时换另一个1024–65535端口，例如28473。脚本只操作固定 Compose 项目 `after-rain` 的服务，不执行全局 Docker 清理或停止其他项目。

`infra/domain.env.example` 提供非敏感配置示例。Actions 会自动生成 `infra/domain.env`、私有 `runtime.json` 及 `nginx.generated.conf`；不要把含密钥的运行配置提交进仓库。直接在宿主机用 `corepack pnpm start:api` 启动时也默认18473，可用进程环境 `API_HOST_PORT=28473` 覆盖；这与 Docker 方式二选一，不能在同一端口同时运行。

生产发布包只包含后端、部署配置和语音模型准备脚本；前端仍由独立 Vercel job 发布。`infra/compose.yml` 的 web 服务仅用于本地 Mock 演示，服务器生产部署使用 `infra/compose.server.yml`。

### SSH_KNOWN_HOSTS 校验失败的定位

`No ED25519 host key is known ...` 表示没有找到匹配连接目标的主机公钥记录，连接尚未进入用户登录阶段。它与登录用的 SSH_PRIVATE_KEY 是两个独立配置。

新版 `Configure and validate pinned SSH host and deploy key` 步骤支持两种 SSH_KNOWN_HOSTS 内容：

1. 从服务器控制台或已验证可信的连接执行 `cat /etc/ssh/ssh_host_ed25519_key.pub`，直接复制完整输出一行 `ssh-ed25519 AAAA...`。脚本会按 SSH_HOST 和 SSH_PORT 自动补齐主机标识；不要复制不带 `.pub` 的私钥。
2. 完整的 known_hosts 记录：22端口是 `host ssh-ed25519 AAAA...`；其他端口是 `[host]:port ssh-ed25519 AAAA...`。host 必须与 SSH_HOST 一致，域名和IP不能混用。已哈希的 known_hosts 记录也支持。

脚本会先用 `ssh-keygen -F` 查找实际目标，再验证公钥格式；找不到匹配时不上传、不自动重写其他主机的记录，也不会使用 ssh-keyscan 自动信任网络返回的密钥。scp/ssh 显式使用生成的 known_hosts 和部署私钥，保留 StrictHostKeyChecking=yes。支持纠正粘贴内容中的 CRLF 和字面量换行，但不会打印 Secret 内容。

修改这个 Secret 时更新 `production` Environment 的同名项。若采用“直接复制公钥”形式，必须先提交并推送新版工作流及 `scripts/configure_deploy_ssh.py` 到 master/main，再点 Run workflow 创建新运行；旧运行的 Re-run 仍使用旧提交中的脚本，不能获得本次修复。

# 场景编辑与模型选择

## 首页入口

首页右上角齿轮图标打开“场景设置”，进入前也可以使用。“显示角色”开关可隐藏或显示人物，隐藏后仍可继续文字和语音互动；切换模型、模式和场景时保留该偏好，刷新恢复默认显示。

- Mock：提供“雨停之前 / Mira”“书页之间 / 林舟”“下一站微光 / 夏澄”三个本地预设，选择后预览，再点击“应用场景”。不调用后端或模型。
- 真实模式：关闭 Mock，先通过“模型”选择 OpenRouter 官方文本模型，再打开设置，输入至少 10 字、最多 2000 字的场景提示。点击“调用模型，生成预览”，检查结果后应用。
- 应用会替换首页品牌、主标题、介绍、地点/时间/天气、角色姓名/年龄/职业、开场白、话题、输入提示、照片说明、角色插画与场景配色，并重新建立会话。浏览器标题同步更新。
- 角色背景、性格和场景也会交给后端对话模型，后续文字和语音交互使用新设定。切换会停止旧声音并清空当前对话。
- 当前场景保存在页面内存，刷新页面恢复默认；没有新增数据库、账号或场景管理后台。

## 画面与声音范围

角色画面由安全的 React SVG 模板绘制，支持长发/短发/盘发、外套/针织衫/夹克、眼镜/星星/围巾，以及肤色、发色、服装与背景色。背景提供咖啡馆、书店、车站模板，模型为描述选择最接近的模板。这里不是文生图或任意 3D 人物生成；原 Mira 保留已有序列帧，新角色使用呼吸、眨眼与说话动画，眉眼与嘴型根据平静、好奇、低落三种状态变化。

照片仍使用现有海边示例素材，说明文字随场景变化。真实模式使用既有 STT/TTS 配置，不自动更换声音或克隆音色。默认 Mock 带录制语音；其他 Mock 角色优先使用设备本地中文语音，设备没有此语音时展示字幕，不播放与角色不符的 Mira 录音。

## 模型选择

`OPENROUTER_MODEL=openrouter/free` 是默认免费路由，可通过环境变量覆盖。前端支持搜索、手动填写完整官方模型 ID、点击列表选择。默认仅免费；关闭筛选后可查看付费模型。价格为目录中的输入/输出美元每百万 token，其他费用以 OpenRouter 为准。模型列表只保留输出为纯文本的条目，列表缓存 5 分钟。目录可用不保证账号权限、配额、隐私设置或 JSON 输出能力可用。

模型弹框只在“可选模型”列表内滚动，通常显示 3 条；较矮窗口根据剩余高度缩小列表。免费路由会选择不同免费模型，角色表现和 JSON 格式可能波动；需要稳定表现时选择固定模型并实测。

## API 与代码边界

- `GET /api/models/openrouter`：公开的官方文本模型目录和后端默认模型，不返回密钥。
- `POST /api/scenes/generate`：`{prompt, model_id?}`，返回完整 `SceneDefinition`；不会悄悄降级成 Mock。
- `POST /api/sessions`：新增可选的 `{model_id, scene}`，后端验证后绑定到该会话；不会改全局角色或模型。
- 场景模型：`apps/api/app/models/scene_definition.py`；生成调度：`services/scene_service.py`；模型协议和 JSON 校验：`infrastructure/providers.py`。
- 前端请求经业务 Hook → transport → http-client；组件没有直接发请求。预设与前端类型位于 `packages/contracts/scenes.json` / `scene.ts`，后端测试验证预设与 Pydantic 合同一致。
- 生成请求设超时、每客户端每分钟 3 次限流及并发控制。模型返回数据需通过字段长度、成年人年龄、枚举和十六进制颜色验证；不会执行模型返回的 HTML、脚本或资源 URL。
- OpenRouter 密钥只在后端使用。本地 `.env.development` 与生产 GitHub Secrets 的方式一致，无需前端密钥。

官方参考：[免费路由](https://openrouter.ai/docs/guides/routing/routers/free-router)、[模型目录 API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)。

## 连续语音与打断

关闭 Mock、等待真实 API 连接后，点击首页“连续语音对话 / 开启对话”，由用户授予麦克风权限。后续直接说话，无需一直按住按钮；“结束对话”关闭采集。原有按住说话模式仍可使用，连续模式启用时该按钮变为“自动聆听”。

- 浏览器 AudioWorklet 本地采集 PCM，采用能量 VAD：持续约 90 毫秒的有效声音触发新轮次，立即停止旧音频、取消旧请求，并让人物进入倾听状态。
- 约 650 毫秒静音自动结束一句；保留约 280 毫秒前置缓冲，避免丢掉开头。每句最多约 18 秒，自动分段，编码为单声道 16-bit WAV；高采样率音频降到 24kHz，低于后端 3MB 限制。
- 麦克风在模型思考和角色播放时保持监听，可再次开口打断。不回放失效轮次的音频、字幕或视觉事件。停止回复不会自动关闭连续监听；“结束对话”、切换模式/模型/场景、断线和离开页面会关闭麦克风。
- 模型生成回复 JSON 后，后端先发送 `reaction` 事件更新表情和支持的动作，再合成声音；仍以当前轮次校验，旧事件不生效。照片卡片在对应语音播放时显示。角色支持倾听、思考、平静/好奇/低落，以及看向窗外、展示照片等既有动作，并非任意动作生成。
- 使用浏览器回声消除与降噪；实际打断效果受设备、扬声器回声、声音大小和噪声影响。耳机有助于减少角色声音误触发。麦克风实机听感需要用目标浏览器和设备验收。
- 这是支持持续监听与打断的 STT → 文本 LLM → 非实时 TTS 链路，没有声称等同 GPT 原生实时语音的延迟、流式识别或音色能力；仍有识别、模型和合成等待。免费模型限流或输出格式错误会明确提示，不自动变成 Mock。
- Mock 保持无需麦克风权限：通过按住演示测试打断与角色状态，连续麦克风对话只在真实模式开启。

实现：`runtime/voice-activity.ts` 管理检测和 WAV，`runtime/voice-capture.ts` 管理麦克风生命周期，`public/audio/voice-capture.worklet.js` 负责采集，`voice-conversation.tsx` 提供独立业务组件。验证覆盖噪声过滤、二次打断、自动提交、WAV 格式、采集分块与旧请求取消；没有自动声称完成目标设备麦克风实测。

参考：[AudioWorkletNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode)、[浏览器回声消除约束](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/echoCancellation)。

## 随机背景音乐

音频放在 `apps/web/public/music`（支持 mp3/wav/ogg/m4a/aac/flac），首页构建时自动收集曲目。每次进入随机选一首，播完后随机选下一首，多首时避免连续重复；新增文件后重新构建/部署，音频文件需随代码一并提交。

设置中的“背景音乐”开关默认开启，关闭立即停止播放，切换模型或场景保留开关状态。音乐低音量播放，角色说话时进一步降低音量；录音、连续语音或页面隐藏时暂停，结束后恢复。页面静音按钮也控制音乐。

浏览器可能阻止未经交互的自动有声播放，因此先尝试播放，被拦截时在首次点击或按键后重试。不会自动申请麦克风权限。音乐使用前端静态资源，不依赖后端或模型服务。
